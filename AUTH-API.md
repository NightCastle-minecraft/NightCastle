# API авторизации SiteGateAuth ↔ сайт

Источник правды для обеих сторон: плагина [`plugins/auth`](plugins/auth) и сайта [`site`](site) (`AuthApiController`). Меняешь контракт — меняй обе стороны и этот файл.

## Общее
- Базовый адрес: `site.url` из `config.toml` плагина, например `https://example.com`.
- Каждый запрос несёт `Authorization: Bearer <AUTH_API_TOKEN>`. Сайт сравнивает токен через `hash_equals`.
  - нет заголовка или токен неверный → `401 {"error":"unauthorized"}`;
  - у сайта пустой `AUTH_API_TOKEN` → API выключено, на любой путь `404`.
- Тело запроса и ответа: JSON, `Content-Type: application/json`, кодировка UTF-8. Время передаётся в секундах Unix (UTC).
- Ник проверяется на обеих сторонах по `^[A-Za-z0-9_]{3,16}$`, сравнение без учёта регистра.
- Ошибки: `400 {"error":"..."}` (кривой запрос), `503 {"error":"db_unavailable"}` (база шарда недоступна).
- Плагин шлёт `User-Agent: SiteGateAuth/<версия>`.

## Аккаунты в трёх базах
`shard = crc32(lower(ник)) % 3 + 1`, crc32 тот же, что у PHP `crc32()`. Ник всегда живёт в одной базе. Плагин номер шарда не считает: этим занимается только сайт.

## Тикет
- Формат `<номер шарда 1..3><43 символа base64url>`: 32 случайных байта, всего 44 символа. Плагин проверяет `^[1-3][A-Za-z0-9_-]{20,64}$`.
- На сайте хранится только `sha256(тикет)`. Тикет одноразовый, живёт 10 минут, привязан к нику и IP.
- Ссылка `url` обязана начинаться с `site.url + "/"`, иначе плагин её не покажет.

## Эндпоинты

### `POST /api/auth/check`
Есть ли у ника живая сессия с этого IP.
```json
→ {"name":"Steve","ip":"1.2.3.4"}
← {"status":"ok","registered":true}
← {"status":"need_auth","registered":false}
```
`ok` = аккаунт есть, IP-сессия жива (`expires_at > now`). Сайт продлевает сессию на 7 дней и обновляет `last_login_at`.

### `POST /api/auth/tickets`
Новый тикет входа. Предыдущие неиспользованные тикеты этого ника гасятся.
```json
→ {"name":"Steve","ip":"1.2.3.4"}
← {"ticket":"2AbC…","url":"https://example.com/auth/2AbC…","expiresIn":600}
```

### `GET /api/auth/tickets/{ticket}`
```json
← {"status":"pending"}    игрок ещё не подтвердил
← {"status":"approved"}   подтвердил: сайт уже создал IP-сессию на 7 дней
← {"status":"denied"}     нажал «Это не я»
← {"status":"expired"}    тикет просрочен или не найден
```

### `POST /api/stats/sessions`
Отыгранные сессии. Повтор той же пары `(ник, start)` дубля не создаёт. Ник без аккаунта пропускается.
```json
→ {"sessions":[{"name":"Steve","start":1795400000,"end":1795403600}]}
← {"accepted":1}
```
Сайт прибавляет `end - start` к `accounts.playtime_seconds` и раскладывает время по дням в `playtime_daily` (UTC). Одна сессия не длиннее 24 часов, остальное обрезается.

### `POST /api/server/heartbeat`
Онлайн для шапки сайта. Плагин шлёт раз в 30 с. Если пульса нет 2 минуты, сайт показывает «оффлайн».
```json
→ {"online":3,"max":20}
← {}
```

## Вход игрока по шагам
1. Плагин: `check`. Пришёл `ok` → игрок сразу на SMP.
2. Пришёл `need_auth` → капча в окне-диалоге, потом `tickets`, потом окно «Нажмите, чтобы авторизоваться» с кнопкой `open_url`.
3. Сайт `/auth/{ticket}`:
   - аккаунта нет → регистрация, ник берётся из тикета;
   - аккаунт есть, но браузер не залогинен → вход паролем;
   - дальше «Войти как Steve с IP 1.2.3.4?» → [Подтвердить] / [Это не я].
4. Плагин раз в 3 с опрашивает `tickets/{ticket}`. На `approved` пускает игрока, на `denied` или `expired` кикает. Через 10 минут без ответа тоже кик.
