## Сначала: собрать диагностику

Эта команда собирает состояние стека в один файл. Паролей и токенов в нём нет, им можно поделиться, когда просите помощи:
```bash
cd /opt/sitegate/infra
{
  echo "== versions"; docker version --format '{{.Server.Version}}'; docker compose version
  echo "== ps"; docker compose ps
  echo "== stats"; docker stats --no-stream
  echo "== memory/disk"; free -h; df -h /
  echo "== ports"; sudo ss -ltnp | grep -E ':(80|443|25565|8780)\s'
  echo "== status"; curl -s https://$(grep '^DOMAIN=' .env | cut -d= -f2)/api/status; echo
  for s in site web mail proxy smp; do echo "== logs $s"; docker compose logs --tail 40 $s 2>&1; done
} > ~/sitegate-diag.txt 2>&1
sed -i -E 's/(token|password|secret)([=: ]+)[^ ,"]+/\1\2<скрыто>/gI' ~/sitegate-diag.txt
less ~/sitegate-diag.txt      # выход: q
```
Перед отправкой всё равно пробегитесь по файлу глазами.

## VPS и Docker

| Симптом | Причина | Решение |
|---|---|---|
| `permission denied while trying to connect to the Docker daemon socket` | Пользователь не в группе `docker`, или вы не перезашли после `usermod` | `sudo usermod -aG docker $USER`, выйти из SSH и зайти снова |
| `required variable DB1_HOST is missing a value` (или другая переменная) | В `.env` пустая обязательная переменная | Заполните её (INSTALL.md, шаг 6) |
| `secret "rcon_pass": ... no such file or directory` | Не созданы секреты | `sh bin/init-secrets.sh` |
| `Bind for 0.0.0.0:80 failed: port is already allocated` (443, 25565) | Порт занят другой программой | `sudo ss -ltnp \| grep ':80 '` покажет кто. Остановите его (INSTALL.md, шаг 2.7) |
| Контейнер в статусе `Restarting` | Падает при старте | `docker compose logs --tail 80 ИМЯ`: причина в последних строках |
| `no space left on device` | Кончился диск | `df -h /`, `du -sh backups servers/SMP`, `docker system df`. Чистка: старые бэкапы, `docker image prune -a` (удалит неиспользуемые образы) |
| После перезагрузки VPS ничего не работает | Не запустился Docker | `sudo systemctl enable --now docker`, затем `docker compose up -d` |
| `git pull`: `Your local changes ... would be overwritten` | Правили файлы репозитория | OPERATIONS.md → «Обновления» |
| Файлы в `servers/` не редактируются (`Permission denied`) | Владелец не вы | `sudo chown -R $USER:$USER servers/`. Если ваш uid не 1000, см. INSTALL.md, шаг 8.2 |

## DNS и HTTPS

| Симптом | Причина | Решение |
|---|---|---|
| В логах `site`: `NXDOMAIN`, `no valid A records` | DNS не указывает на VPS или ещё не разошёлся | `dig +short A example.com @1.1.1.1` должен вернуть IP VPS. Подождите, затем `docker compose restart site` |
| В логах `site`: `Timeout during connect`, `connection refused` | Закрыт порт 80 или 443: ufw, фаервол хостинга | INSTALL.md, шаг 2.8. Проверка с ПК: `curl -I http://example.com` |
| В логах `site`: `too many certificates already issued` | Лимит Let's Encrypt: 5 одинаковых сертификатов в неделю (часто из-за удаления тома `sg-site-data`) | Подождите до недели. Не удаляйте `sg-site-data` |
| `dig` возвращает `104.x.x.x` / `172.67.x.x` | Включён прокси Cloudflare (оранжевое облако) | Сделайте облако серым (DNS only) |
| Браузер: `ERR_SSL_PROTOCOL_ERROR`, «Подключение не защищено» | Сертификат ещё не получен | Смотрите логи `site`, причины выше |
| `www.example.com` не открывается | Нет A-записи `www` | INSTALL.md, шаг 3.1 |
| `curl https://example.com` с VPS работает, а у вас в браузере нет | Кеш DNS у вас на ПК | Подождите или сбросьте кеш DNS (Windows: `ipconfig /flushdns`) |

## Базы и миграции

| Симптом | Причина | Решение |
|---|---|---|
| `FAIL DB1: SQLSTATE[HY000] [2002] Connection timed out` / `Connection refused` | До базы не достучаться: неверный хост или порт, хостинг не пускает IP VPS | Проверка из шага 4.1 INSTALL.md. Разрешите IP VPS у хостинга |
| `[2002] php_network_getaddresses: getaddrinfo ... failed` | Неверный хост, опечатка в `DBn_HOST` | Исправьте `.env`, `docker compose up -d web` |
| `[1045] Access denied for user` | Неверный пользователь или пароль. Частая причина: `$` или `#` в пароле без кавычек | Пароль в одинарных кавычках в `.env` (INSTALL.md, шаг 6.2) |
| `[1044] Access denied ... to database` | У пользователя нет прав на эту базу | Дайте пользователю все права на базу у хостинга |
| `[1049] Unknown database` | Неверное имя базы | Исправьте `DBn_NAME` |
| Вариант Б: `[2002] ... getaddrinfo for db failed` | Контейнер `sg-db` не запущен | `docker compose up -d db`, подождать 20 секунд |
| `[1040] Too many connections` | Хостинг ограничивает число соединений | Выключите постоянные соединения: `DB_PERSISTENT: "0"` (CONFIGURATION.md, раздел 9.6) |
| На сайте у части игроков «база временно недоступна» | Одна из трёх баз не отвечает: в ней живёт примерно треть ников | Смотрите `docker compose logs --tail 50 web`, проверьте эту базу у хостинга. Игроки с живой IP-сессией в игру заходят и так |
| На дашборде админки красный размер базы | База больше 3 ГБ | Узнайте лимит у хостинга, почистите или перенесите базу. Тяжёлые логи плагинов (CoreProtect и т.п.) держите в их локальном SQLite, а не в этих базах |
| В админке «Игроки» каждый ник по три раза | Одна база вписана во все три `DBn_*` | Это нормально (INSTALL.md, шаг 4) |

## Сайт

| Симптом | Причина | Решение |
|---|---|---|
| «Что-то пошло не так» / ошибка 500 | Ошибка PHP | `docker compose logs --tail 80 web`: там текст ошибки. Чаще всего это база (раздел выше) |
| Страница без стилей, кривая вёрстка после обновления | Старый CSS в кеше браузера | `Ctrl+Shift+R`. Адреса CSS и JS содержат хеш, так что проблема разовая |
| «Форма устарела. Обновите страницу и попробуйте ещё раз.» | Истекла сессия формы (CSRF) или браузер блокирует cookies | Обновите страницу и отправьте заново. Разрешите cookies для сайта |
| `429 Too Many Requests` | Лимит Caddy: 120 запросов в минуту с IP, 20 попыток входа в минуту | Подождите минуту. Лимиты в CONFIGURATION.md, раздел 4 |
| «Слишком много неверных попыток. Попробуйте через 15 минут.» при входе игрока | 5 неверных паролей за 15 минут на пару IP + ник | Подождите 15 минут или сбросьте пароль («Забыли пароль?») |
| Не входит в админку, пароль точно верный | Лимит попыток входа в админку | Подождите 15 минут. Сбросить пароль: `docker exec -it sg-web php bin/create-admin.php admin --reset` |
| Не загружается фон главной | Файл больше 5 МБ или не JPG/PNG/WebP | Уменьшите картинку |
| В шапке сайта `OFFLINE`, хотя сервер работает | Пульс от SiteGateAuth не приходил больше 2 минут | `docker compose logs --tail 50 proxy`: ищите ошибки связи с сайтом |
| На странице входа или в письмах чужой адрес сервера | Не заполнено «IP для показа» или `GAME_ADDRESS` | Админка → «Настройки» → «IP для показа»; `GAME_ADDRESS` в `.env` |

## Вход в игру

### Кики SiteGateAuth (тексты из `config.toml`)

| Текст в игре | Причина | Решение |
|---|---|---|
| **«Вход временно закрыт»** | Плагин выключил вход для всех. Причина в логе прокси: нет токена, не читается `config.toml` или версия Velocity не 4.3.1 | `docker compose logs proxy \| grep -i sitegate`. Токен: `ls -l secrets/auth_api_token` и `token-file` в конфиге (INSTALL.md, шаг 11). Версия: `velocity.jar` из `plugins/libs` |
| **«Сайт авторизации недоступен»** | Прокси не достучался до сайта, а живой сессии у игрока нет | `docker compose ps` (работает ли `site` и `web`), `url` в `config.toml` плагина, `curl -s https://example.com/api/status` на VPS |
| **«Нужен клиент Minecraft 26.3»** | Клиент другой версии | Играть на 26.3 |
| **«Недопустимый ник»** | Ник короче 3 или длиннее 16 символов, или есть символы кроме латиницы, цифр и `_` | Сменить ник в лаунчере |
| **«Слишком много попыток входа»** | Больше 5 подключений в минуту с одного IP | Подождать минуту. Если за одним IP много игроков (общежитие, клуб), увеличьте `logins-per-minute` |
| **«Капча не пройдена»** | 3 неверных ответа подряд | Подождать 5 минут (`ban-minutes`) |
| **«Время на вход истекло»** | Не подтвердил вход на сайте за 10 минут | Зайти снова и сразу подтвердить |
| **«Вход отклонён на сайте»** | На сайте нажали «Это не я» | Если это был не игрок, пусть сменит пароль и сбросит сессии в кабинете |

### Другие проблемы со входом

| Симптом | Причина | Решение |
|---|---|---|
| В списке серверов «Не удаётся подключиться» / `Connection refused` / `timed out` | Прокси не работает, или порт 25565 закрыт | `docker compose ps proxy`, `docker port sg-proxy`. С ПК: `timeout 5 bash -c '</dev/tcp/example.com/25565' && echo ok`. ufw и фаервол хостинга (INSTALL.md, шаг 2.8) |
| Кнопка «Нажмите, чтобы авторизоваться» не открывает браузер | В системе игрока не задан браузер по умолчанию, или лаунчер запущен в песочнице, откуда ссылки не открываются | Задать браузер по умолчанию; запустить игру другим лаунчером |
| На сайте «Ссылка устарела или уже использована» | Ссылка живёт 10 минут и одноразовая | Перезайти в игру за новой ссылкой |
| Подтвердил на сайте, а игра всё ждёт | Прокси не видит подтверждения: связь с сайтом | Подождите 3–5 секунд. Дальше смотрите `docker compose logs --tail 50 proxy` |
| После подтверждения: `Unable to connect you to smp`, `Unable to verify player details`, `This server requires you to connect with Velocity` | SMP не принимает данные от прокси: не включён `proxies.velocity` или секрет не совпадает | INSTALL.md, шаг 8.5. Сравните `secret` в `paper-global.yml` с `cat secrets/forwarding_secret`, затем `docker compose restart smp` |
| `You are not white-listed on this server!` | Включён вайтлист SMP | `white-list=false` в `server.properties` или `docker exec -i sg-smp rcon-cli whitelist add Steve` |
| `Failed to verify username!` | В `velocity.toml` включён `online-mode` | `online-mode = false`, `docker compose restart proxy` |
| Игра пускает без капчи и сайта | У игрока живая IP-сессия (7 дней с того же IP), так и задумано | Выйти на всех устройствах: кабинет → «Выйти на всех устройствах» или админка → «Сбросить сессии» |
| У всех игроков в логах один IP | Перед прокси стоит что-то, что подменяет IP (anycast, DDoS-защита) | Включить у неё PROXY protocol и в `velocity.toml` → `haproxy-protocol = true`. Без такой защиты не включайте |
| Сервер не появляется в списке, а по IP работает | Кеш DNS у игрока | Подождать или добавить сервер по IP |

## Почта

Где смотреть: `docker logs sg-mail 2>&1 | grep status= | tail` — судьба каждого письма; `docker compose logs --tail 50 web` — ошибки отправки со стороны сайта.

| Симптом | Причина | Решение |
|---|---|---|
| `status=deferred ... Connection timed out` для всех почтовиков | Хостинг закрыл исходящий порт 25 | INSTALL.md, шаг 2.9: попросить открыть |
| `status=bounced ... 550-5.7.25` (Gmail) | Нет PTR, или PTR не совпадает с `mail.example.com` | INSTALL.md, шаг 3.3 |
| `550-5.7.26 ... unauthenticated` (Gmail) | Не проходят SPF/DKIM | Проверить записи: `dig +short TXT example.com`, `dig +short TXT sg1._domainkey.example.com`. DKIM: INSTALL.md, шаг 14.1 |
| Письмо приходит в «Спам» | Нет PTR, свежий домен или IP с плохой репутацией | Поставьте PTR, проверьте письмо на mail-tester.com. Репутация растёт со временем |
| В «Показать оригинал»: `DKIM: FAIL` | Запись DKIM в DNS не совпадает с ключом в томе | Заново склеить и вписать запись (INSTALL.md, шаг 14.1). Если том `sg-mail-dkim` пересоздавался, ключ новый |
| В логах `sg-mail` ничего нет, на сайте «письмо не ушло» | Сайт не достучался до почтового контейнера | `docker compose ps mail`, `docker compose logs --tail 30 mail` |
| Игрок не получил письмо подтверждения | Опечатка в адресе, письмо в спаме, лимит 3 письма в час | В кабинете игрока: сменить почту / «Отправить ещё раз». Админ видит почту в «Игроки» |

## Панель

| Симптом | Причина | Решение |
|---|---|---|
| Туннель: `bind [127.0.0.1]:8780: Address already in use` | На ПК уже открыт туннель или порт 8780 чем-то занят | Закройте окно со старым туннелем. Локальный порт должен быть именно 8780: панель принимает только адрес `localhost:8780`, другой порт она отвергнет |
| Браузер: «Не удаётся получить доступ к сайту» на localhost:8780 | Туннель не открыт или закрылся | Запустите `ssh -N -L 8780:127.0.0.1:8780 ubuntu@203.0.113.10` и не закрывайте окно |
| В окне туннеля: `channel 2: open failed: connect failed: Connection refused` | Панель на VPS не запущена | `systemctl status sitegate-panel`, `journalctl -u sitegate-panel -n 30` |
| «Неверный пароль», хотя он верный | Браузер подставил старый сохранённый пароль, или вход заблокирован после 10 ошибок | Наберите вручную. Блокировка снимается через 15 минут. Новый пароль: INSTALL.md, шаг 15.2 |
| Панель не стартует: `PermissionError ... panel.json` | Пароль задавали через `sudo`, файл стал root-овым | `sudo chown -R $USER:$USER /opt/sitegate/infra/panel/data`, `sudo systemctl restart sitegate-panel` |
| В панели все контейнеры «не запущен», хотя работают | Пользователь службы не в группе `docker` | `sudo usermod -aG docker ubuntu`, `sudo systemctl restart sitegate-panel` |
| Консоль и бэкап: «save-all не прошёл», ошибка RCON | Пароль RCON в `server.properties` не совпадает с `secrets/rcon_pass` или `enable-rcon=false` | INSTALL.md, шаг 8.4, затем перезапуск SMP |
| Не сохраняется конфиг: `Permission denied` | Файлы в `servers/` принадлежат другому пользователю | `sudo chown -R $USER:$USER /opt/sitegate/infra/servers` |
| Ссылка «Сайт» в панели ведёт на example.com | Не задан `SG_SITE_URL` | INSTALL.md, шаг 15.1 |

## Магазин

| Симптом | Причина | Решение |
|---|---|---|
| На сайте у товара вместо кнопки «Временно недоступно» | Плагин не прислал этот код: нет файла `products/<код>.yml` или не сделан reload | Создайте файл с тем же кодом, затем `docker exec -i sg-smp rcon-cli shop reload` |
| `/shop`: «Магазин на сервере не настроен» | У SiteGateShop нет токена | `token-file` в конфиге плагина (INSTALL.md, шаг 10), `ls -l secrets/shop_api_token`, `docker compose up -d --force-recreate smp` |
| `/shop`: «Сайт магазина сейчас недоступен» | SMP не достучался до сайта | `url` в конфиге плагина. В логах SMP ищите `SiteGateShop` |
| `/shop`: «Аккаунта на сайте пока нет» | Игрок ни разу не входил через сайт под этим ником | Зайти через сайт |
| Заказ долго в статусе «ждёт выдачи» | `require-online: true`, а игрок не в игре. Или плагин не опрашивает сайт | Выдастся при входе игрока. Иначе: `docker compose logs smp \| grep -i sitegateshop` |
| Заказ в статусе «ошибка выдачи» | Команда выдачи упала: нет нужного плагина (LuckPerms и т.п.), опечатка в команде | Исправьте `products/<код>.yml` → `shop reload` → админка → «Магазин» → «Заказы» → «Выдать снова». Или «Отменить и вернуть»: монеты вернутся игроку |
| Монеты списались, предмет не пришёл, статус «выдан» | Команда выполнилась, но ничего не дала. У `give` при полном инвентаре предметы падают на землю рядом с игроком | Выполните команду из `products/<код>.yml` вручную в консоли, подставив ник, и посмотрите ответ |

## Лаги и память

| Симптом | Причина | Решение |
|---|---|---|
| SMP внезапно перезапускается, в `docker inspect -f '{{.State.OOMKilled}}' sg-smp` стоит `true` | Упёрся в `mem_limit` | `SMP_MEMORY` меньше или `mem_limit` больше (CONFIGURATION.md, раздел 3) |
| Внезапно умирают разные контейнеры, в `sudo dmesg \| grep -i oom` есть записи | Кончилась память всего VPS | Уменьшите `SMP_MEMORY`, включите swap (INSTALL.md, шаг 2.5), берите VPS побольше |
| TPS ниже 20, блоки «тормозят» | Нагрузка на основной поток | `view-distance` и `simulation-distance` 6–8, меньше мобов и ферм. Отчёт по нагрузке — плагин spark |
| Лагает только вход (капча, окно) | Сайт или база медленно отвечают | `docker compose logs proxy`. Хостинг баз далеко от VPS — каждый запрос ждёт |

## Частые вопросы

**Можно без домена, по IP?** Нет. Сертификат HTTPS, письма и ссылки из игры требуют домен. Домен в зоне вроде `.xyz` стоит копейки.

**Игроки с лицензией тоже идут через сайт?** Да. Проверка лицензии выключена для всех, ник защищает пароль на сайте. Лицензионным игрокам ничего не мешает: их скин отображается как обычно, если на сервере стоит плагин скинов.

**Можно пускать клиентов других версий (ViaVersion)?** Нет. Вход построен на окнах-диалогах в фазе конфигурации, а плагин рассчитан на протокол 26.3.

**Bedrock (Geyser)?** Нет: у Bedrock нет этих окон-диалогов.

**Несколько игровых серверов (лобби + выживание)?** Velocity это умеет: добавьте сервер в `[servers]` в `velocity.toml` и в compose. Но инструкция и панель рассчитаны на один SMP, остальное настраиваете сами. SiteGateShop ставится на тот сервер, где выдаются покупки.

**Как принимать реальные деньги?** Платёжной системы в комплекте нет: монеты начисляет админ. Интеграцию с платёжкой придётся писать самим.

**Сайт на английском?** Тексты сайта на русском, они лежат в `site/templates/`. Перевод — правка шаблонов и пересборка `web`.

**Можно включить оранжевое облако Cloudflare для сайта?** Не советуем. Для игры облако должно быть серым всегда. Для сайта оранжевое мешает получению сертификата и ломает лимиты по IP.

**Можно поставить на домашний компьютер?** Технически на Linux-машине с белым IP — да, по той же инструкции. На Windows и с серым IP (за NAT провайдера) — нет.

**Сколько это стоит?** Код бесплатный для некоммерческого использования ([LICENSE.md](LICENSE.md)). Платите только за VPS, домен и (по желанию) хостинг баз.
