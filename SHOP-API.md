# API магазина SiteGateShop ↔ сайт

Источник правды для плагина [`plugins/shop`](plugins/shop) и сайта [`site`](site) (`ShopApiController`). Меняешь контракт, меняй обе стороны и этот файл.

## Общее
- Базовый адрес: `site.url` из `config.yml` плагина, например `https://example.com`.
- Каждый запрос несёт `Authorization: Bearer <SHOP_API_TOKEN>`. **Это отдельный токен, не тот, что у SiteGateAuth.** У SMP своя зона ответственности: если утечёт токен магазина, входом в игру он не управляет.
  - неверный токен → `401 {"error":"unauthorized"}`;
  - у сайта пустой `SHOP_API_TOKEN` → `404`, магазин выключен.
- JSON в UTF-8. Ошибка базы → `503 {"error":"db_unavailable"}`.
- Плагин шлёт `User-Agent: SiteGateShop/<версия>`.

## Деньги
Монеты живут на сайте (кошелёк аккаунта, таблица `shop_wallets` в DB1). Пополняет админ: админка сайта (`/admin/shop/wallet`) или панель. Игрок покупает на `/shop`: списание и заказ идут одной транзакцией. Плагин денег не видит, он только выдаёт заказы.

## Товары
- На сайте: название, цена, описание, **код**.
- В плагине: `plugins/SiteGateShop/products/<код>.yml`, там команды выдачи и `require-online`.
- Купить можно только товар, код которого плагин прислал сайту (`/api/shop/codes`). Иначе заказ висел бы вечно.

## Эндпоинты

### `GET /api/shop/pending?limit=50`
Оплаченные и ещё не выданные заказы, по порядку.
```json
← {"orders":[{"id":17,"name":"Steve","code":"vip_30d","title":"VIP на 30 дней"}]}
```

### `POST /api/shop/delivered`
Что плагин выдал (`delivered`) и что не смог (`failed`, команда вернула ошибку). Меняет только заказы в статусе `pending`, поэтому повтор безопасен.
```json
→ {"delivered":[17,18],"failed":[{"id":19,"error":"команда не выполнилась: lp user Bob ..."}]}
← {"updated":3}
```
Заказ с ошибкой админ видит в `/admin/shop/orders`: может вернуть его в очередь или отменить с возвратом монет.

### `POST /api/shop/codes`
Плагин сообщает, какие товары умеет выдавать: при запуске и после `/shop reload`. Список заменяется целиком.
```json
→ {"codes":[{"code":"vip_30d","online":false},{"code":"diamonds_16","online":true}]}
← {"count":2}
```

### `GET /api/shop/balance/{ник}`
Для команды `/shop` в игре.
```json
← {"registered":true,"balance":120}
```

## Выдача по шагам
1. Плагин раз в `poll-seconds` (15 с) и через 3 с после входа любого игрока берёт `pending`.
2. Заказ, для которого нет `products/<код>.yml`, остаётся в очереди: в лог одно предупреждение.
3. `require-online: true` и игрока нет → ждёт до входа. Иначе команды выполняются от консоли по порядку. Подстановки: `{player}`, `{uuid}` (офлайновый UUID, как его выдаёт Velocity), `{order}`, `{title}`.
4. Результат сразу пишется в `plugins/SiteGateShop/delivered.json`, потом уходит на сайт в `delivered`. Если сайт не ответил или сервер упал, при следующем опросе уходит только подтверждение, повторной выдачи нет.
