# Как устроен SiteGate

## Компоненты

| Компонент | Где | Что делает |
|---|---|---|
| **SiteGateAuth** | плагин Velocity 4.3.1 | Держит игрока в фазе конфигурации, показывает капчу и окно со ссылкой, ждёт подтверждения на сайте, пускает на SMP |
| **SiteGateShop** | плагин Paper/Leaf 26.3 | Забирает с сайта оплаченные заказы и выполняет команды выдачи |
| **Сайт** | `site/`, PHP 8.3 + Apache | Аккаунты, вход по ссылке из игры, кабинет, магазин, админка, API для обоих плагинов |
| **Caddy** | контейнер `sg-site` | HTTPS (Let's Encrypt), лимиты запросов, отдаёт сайт |
| **Postfix** | контейнер `sg-mail` | Письма игрокам, DKIM-подпись. Только отправка, наружу не открыт |
| **SMP** | контейнер `sg-smp` | Игровой сервер. Портов наружу нет, вход только через прокси |
| **Панель** | служба systemd, `infra/panel/panel.py` | Управление стеком через docker CLI и RCON, на `127.0.0.1:8780` |

## Вход игрока

```
клиент 26.3 ── handshake/login ──► Velocity
                                   │ PreLogin: проверка ника, версии клиента, лимит входов с IP, бан IP
                                   │ PostLogin (ещё фаза конфигурации, на SMP игрок не попал)
                                   ├─► POST /api/auth/check {ник, IP}
                                   │      ok        → сразу на SMP (живая IP-сессия)
                                   │      need_auth → окно-капча (диалог Minecraft)
                                   │                  → POST /api/auth/tickets → окно «Нажмите, чтобы авторизоваться» (open_url)
                                   │                  → раз в 3 с GET /api/auth/tickets/{тикет}
                                   │                       approved → на SMP; denied/expired → кик
                                   ▼
                                  SMP (modern forwarding: UUID и IP игрока передаются с подписью секретом)
```
- **Фаза конфигурации + диалоги.** С 1.21.6 сервер может показать окно-диалог ещё до входа в мир. SiteGateAuth держит игрока в этой фазе (`EventTask` в `PostLoginEvent`) и шлёт пакеты `show_dialog` / `clear_dialog` / keepalive сам. Отдельный «лимбо-сервер» не нужен.
- **Внутренности Velocity** трогает только один класс, `net/ConfigChannel`: поле `DialogShowPacket.nbt` через рефлексию, перехват `ServerboundCustomClickActionPacket`, имя `handler` в pipeline Netty. Если в новой версии Velocity чего-то нет, плагин закрывает вход для всех (fail closed).
- **Тикет**: `<номер базы><43 символа base64url>`, 32 случайных байта. В базе лежит только sha256. Живёт 10 минут, одноразовый, привязан к нику и IP.
- **IP-сессия**: после подтверждения 7 дней игра пускает с того же IP без сайта. «Выйти на всех устройствах» в кабинете гасит все сессии.
- **Сайт недоступен**: игроки с живой сессией заходят по локальному кешу плагина, новых не пускает.
- **Наигранное время**: плагин копит сессии в очереди на диске и отправляет пачками. Повтор не создаёт дублей: ключ (аккаунт, начало сессии).

## Аккаунты в трёх базах

`база = crc32(lower(ник)) % 3 + 1`. Ник всегда живёт в одной базе, поиск по нику идёт в одну базу. DB1 вдобавок хранит таблицы сайта: новости, правила, страницы, настройки, админы, магазин, пульс.

Зачем: хостинги часто ограничивают размер одной базы. Три базы делят нагрузку и место. Можно указать одну базу во всех трёх наборах, тогда шардирования фактически нет.

Схема совместима с MySQL 8 и MariaDB 10.4–10.6: `utf8mb4_unicode_ci`, без JSON, CHECK и коллаций `0900`. Миграции лежат в `site/migrations/site` (только DB1) и `site/migrations/shard` (все три базы). У каждой базы своя таблица `schema_migrations`.

## Магазин

- Монеты лежат на кошельке аккаунта (DB1). Покупка — это списание и заказ **в одной транзакции**. Двойной клик ловится одноразовым nonce формы.
- Начисляет монеты админ: админка или панель. Приёма платежей нет.
- Купить можно только товар, код которого прислал плагин (`/api/shop/codes`), иначе заказ висел бы вечно.
- SiteGateShop раз в 15 секунд и сразу после входа игрока забирает `pending`. Результат выдачи пишется в `delivered.json` **до** подтверждения сайту. Если сайт не ответил или сервер упал, при следующем опросе уходит только подтверждение, повторной выдачи нет.
- Команда упала → заказ `failed`. Админ может вернуть его в очередь или отменить с возвратом монет.
- У магазина свой токен API, не тот, что у входа.

## Почта

- Postfix (`boky/postfix`) только на отправку, DKIM подписывает rspamd. Сайт шлёт письма по SMTP внутри docker-сети, без внешних библиотек (`site/src/Mailer.php`).
- Письма: подтверждение почты (ссылка на 24 ч), приветствие после подтверждения, сброс пароля (1 ч, одноразово, сбрасывает все входы).
- Почта при регистрации обязательна. Форма «Забыли пароль?» отвечает одинаково, есть аккаунт или нет: по ней нельзя узнать, чей ник существует.
- Для доставки нужны SPF, DKIM, DMARC и PTR (см. INSTALL.md). BIMI (логотип в почтовом клиенте) можно добавить, но Gmail показывает его только с платным сертификатом VMC/CMC.

## Защита

- Капча в игре, лимиты: 5 входов в минуту с IP, бан IP на 5 минут за проваленную капчу, 5 неверных паролей за 15 минут на пару IP+ник, 5 регистраций в час с IP. На регистрации на сайте ещё пример на сложение и скрытое поле-ловушка.
- Пароли хранятся через `password_hash`, CSRF стоит на каждой форме, строгий CSP без inline-скриптов.
- Регулярки на входе (ники, тикеты) с флагом `D`: иначе `$` пропускает перевод строки.
- CSS и JS подключаются с версией по хешу содержимого (`asset()`): кеш браузера не держит старые стили после обновления.
- Панель слушает только localhost, защищена паролем (PBKDF2), проверкой Host (от DNS rebinding), заголовком `X-Panel` и Origin (от CSRF).

## Почему так (кратко)

| Решение | Почему | От чего отказались |
|---|---|---|
| Вход через сайт, пароль в игре не вводится | Пароль не светится в чате и логах сервера, регистрация с почтой и кабинетом в одном месте | Классическая `/login` в чате |
| Фаза конфигурации вместо лимбо-сервера | Нет отдельного мира и лишнего процесса, игрок не видит ничего, кроме окон | Лимбо-сервер, LimboAPI |
| Три базы с шардированием по нику | Лимиты размера базы у хостингов | Одна большая база |
| Свой SMTP-клиент без зависимостей | Postfix в той же сети пускает без логина, а кода около 150 строк | PHPMailer |
| Панель на stdlib Python за SSH-туннелем | Нечего ломать из интернета, нечего обновлять | Веб-панель наружу |
| Velocity строго 4.3.1 build 45 | Плагин опирается на внутренние классы прокси | «Любая версия» |
